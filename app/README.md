# Meridian — Churn Predictive Dashboard (FastAPI + React)

An interactive dashboard for the predictive analysis: live single-customer scoring, model
performance, churn drivers, and the ranked retention priority list. It uses a **lean model** that
keeps only the relevant fields — see [`MODEL.md`](MODEL.md) for the model, results, required fields
and the columns deliberately neglected.

```
app/
  backend/     FastAPI + the lean model (train.py builds artifacts/, main.py serves them)
  frontend/    React (Vite) single-page dashboard
  MODEL.md     model, results, required fields, neglected columns (generated by train.py)
```

## Run it (two terminals)

**1. Backend** (from `app/backend`):
```bash
pip install -r requirements.txt       # first time
python train.py                       # first time: builds artifacts/ (model, metrics, priority list)
python -m uvicorn main:app --port 8137
```
Use `python -m uvicorn` (not bare `uvicorn`) so it runs in the same Python that trained the model —
otherwise a different scikit-learn version warns on load.

**2. Frontend** (from `app/frontend`):
```bash
npm install                           # first time
npm run dev
```
Open the URL it prints (**http://localhost:5173**). Vite proxies `/api/*` to the backend on 8137,
so no CORS setup is needed. If 5173 is busy it uses the next port — open whatever it prints.

## API
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | liveness + model name |
| GET | `/api/metrics` | holdout metrics, tier counts, drivers, feature importance |
| GET | `/api/fields` | input field schema (drives the form) |
| GET | `/api/priority?tier=&limit=&q=` | ranked priority list (filter/search) |
| POST | `/api/predict` | score one customer → probability, tier, balance-at-risk, reasons, **retention plan** |

`/api/predict` also returns a **tailored retention plan** (`retention_plan`): a tier-level strategy
plus specific actions matched to the customer's own risk signals (reactivation, cross-sell,
onboarding, complaint recovery, RM assignment, etc.), each with a channel and a planning cost in AED.
The playbook lives in `backend/ml.py` → `retention_plan()`. Recommendations only — effectiveness is
tested in the pilot (RCT).

Example:
```bash
curl -X POST http://localhost:8137/api/predict -H "Content-Type: application/json" \
  -d '{"customer_segment":"Affluent","tenure_years":0.5,"avg_monthly_balance":120000,
       "num_products":1,"digital_engagement_score":15,"complaint_count_last_year":2,
       "nps_score":-20,"relationship_manager_assigned":0,"last_transaction_days_ago":120}'
```

## Rebuild the model
Edit the field set or algorithm in `backend/ml.py` / `backend/train.py`, then
`python train.py` regenerates `artifacts/` **and** `MODEL.md`. Restart the backend to pick it up.

> Predictive/descriptive tool for outreach prioritisation only — not credit, pricing or
> eligibility. Associations are not causation; the pilot (an RCT) tests cause.
